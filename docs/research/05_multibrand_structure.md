## 0. 役員向けエグゼクティブサマリ（先に読む 1 ページ）

### 何を決めたいか
**事業ごとにトーン（雰囲気・色・動き）を変えながら、サイト全体は同じ会社のものに見える** ための設計ルール。これを最初に決めないと、ページごとにバラバラなサイトになる。

### 上司・経営層の希望（議事より）
- AI 事業は「テック系の青」、他事業はそれぞれの特性に合わせる
- 役員から「丸めて欲しい」と言われるくらい尖る
- ストーリーテラー的な構成（トップ → 各事業ページへ引き込む）
- 顔出しなしブランディング
- 高画質素材で「数百万かけた感じ」を出す

### 3つの構造案

| 案 | 共通範囲 | 可変範囲 | 一貫性 | 尖り | 運用負荷 |
| --- | --- | --- | --- | --- | --- |
| **A: テンプレ型** | レイアウト全体 | メインカラーのみ | ◎ | × | ◎ |
| **B: 中庸型（推奨）** | ナビ・フッター・タイポ・グリッド・コピールール | カラー・写真トーン・モーション・顔出し様式 | ◯ | ◯ | ◯ |
| **C: 分断型** | フッターのみ | ほぼ全部 | × | ◎ | × |

### 推奨: **案 B（中庸型）**

理由:
- 上司の「尖り」と「事業別トーン分け」の両方に対応できる
- 案 C のように完全分断すると、**SEO・運用・採用** すべてで負荷が爆発する
- 案 A だと「数百万かけた感じ」が出ない（テンプレに見える）
- 案 B は **Apple のサイト構造**（`/business`, `/education`, `/music` がそれぞれ違う表情だが Apple は一貫）と同じ思想

### 期待効果
- AI OPS: テック青で「真剣な技術企業」感を出す
- コールセンター: 現場・環境ショットで「採用に効く」リアル感
- 財務: 静謐・編集的な誌面感で「重厚な信頼」

### リスクと対策
- **リスク**: 「事業ごとの可変範囲」を曖昧にすると、現場でブランド統制が効かない
- **対策**: 本ドキュメント Section 4 で **メタ層 / 事業層を厳格に明文化**。実装時にデザインルール SSOT として運用

### 次のステップ
1. 役員レビュー → 案 B 合意
2. Phase C: 顔出しなし様式の絞り込み
3. Phase D: KPI 再定義 + 素材発注書

## 1. 前提と問い

### 1.1 解こうとしている問題

打ち合わせ議事（`request260430.md`）で出た以下の要求は、放置すると **互いに衝突する**:

| 要求 | 衝突相手 |
| --- | --- |
| 事業ごとにトーンを切り替えたい | サイト全体の一貫性を失う |
| 役員から「丸めて」と言われるくらい尖りたい | 業界の信頼性ベースライン |
| ストーリーテラー的な引き込み | 各事業ページの独立した役割（採用 / 法人営業 / 提携先窓口） |
| 顔出しなし | メンバー紹介や採用での説得力 |

これらを **構造のレベルで両立させる** のが本フェーズの目的。

### 1.2 マルチブランドとは

ここで言うマルチブランドは「サブブランドを作る」という意味ではない。**1 つのコーポレートブランド（GIFT）の中で、事業ごとに表情を変えていい範囲を定める** こと。

Apple のサイトを思い浮かべると分かりやすい:
- `apple.com/iphone` と `apple.com/business` は **明らかに違う雰囲気**
- でも **Apple のサイトであること** は誰も疑わない
- これは **ナビ・フッター・タイポ・グリッド** が完全に共通だから

GIFT も同じ構造を作る。

## 2. 「メタ層」と「事業層」の概念定義

### 2.1 メタ層（全事業共通・絶対不変）

**サイト全体で同一であるべき要素**:

| カテゴリ | 具体内容 |
| --- | --- |
| ナビ | グローバルヘッダー、ハンバーガーの開き方、ドロワーのレイアウト |
| フッター | 会社情報、グループ事業一覧、SNS、コピーライト |
| ロゴ | サイズ規則、配置位置、配色バリエーション |
| タイポ階層 | H1/H2/H3 のサイズスケール、本文の line-height |
| グリッド | 最大幅、左右マージン、セクション間スペーシング |
| 「対比の1行」コピールール | rebita 学びの転用。各事業ページのヒーローで採用するコピー様式 |
| 数値タイポ表現 | 大きい数字 + 細い説明テキストの様式 |
| アニメーションの基底ルール | スクロール時の出現遅延、easing カーブ |

### 2.2 事業層（事業ごとに可変・自由領域）

**事業ごとに表情を変えていい要素**:

| カテゴリ | 可変内容 | 例 |
| --- | --- | --- |
| メインカラー | 1色 | AI OPS = テック青 / コールセンター = 暖色系 / 財務 = ダーク・グリーン or グレー |
| アクセントカラー | 1色 | メインの補色 |
| 写真トーン | 撮影スタイル | AI OPS = データ可視化・抽象 / コールセンター = 現場・環境 / 財務 = 静謐・編集 |
| モーション強度 | 控えめ⇔派手 | AI OPS = 派手（テック感）/ 財務 = 控えめ（重厚） |
| 顔出しなし様式 | 表現方法 | AI OPS = データインフォグラフィック / コールセンター = 環境ショット / メンバー = イラスト |
| 章立て構造 | HISTORY/SOLUTION/CASE の繰り返し回数や順序 | 事業の特性で調整可 |

### 2.3 グレーゾーン（事業ごとに変えるか議論余地）

| カテゴリ | グレー理由 |
| --- | --- |
| 見出しフォント | 全事業統一が無難だが、AI OPS だけサンセリフ寄りにするなど分ける選択肢もあり |
| 動画 vs 静止画の比率 | 統一すると運用が楽、事業ごとに変えると「らしさ」が出る |
| CTA ボタンの形状 | 全事業統一が望ましい。色だけ可変 |

## 3. 3 案の比較

### 3.1 構造の違い（一覧）

| 項目 | 案 A: テンプレ型 | 案 B: 中庸型（推奨） | 案 C: 分断型 |
| --- | --- | --- | --- |
| ナビ・フッター | 完全共通 | 完全共通 | フッターのみ共通 |
| タイポ階層 | 完全共通 | 完全共通 | 事業ごとに別 |
| グリッド | 完全共通 | 完全共通 | 事業ごとに別 |
| メインカラー | 1色だけ可変 | 1+1色可変 | 完全自由 |
| 写真トーン | 統一 | 事業ごと可変 | 事業ごと可変 |
| モーション | 統一 | 事業ごと可変 | 事業ごと完全自由 |
| ヘッダーロゴの色変化 | なし | あり（事業層で淡色変化） | あり（自由） |
| ドメイン | 同一 | 同一 | 同一（or サブドメイン分割） |
| 実装複雑度 | 低 | 中 | 高 |
| 運用負荷 | 低 | 中 | 高 |
| ブランド一貫性 | ◎ | ◯ | × |
| 「尖り」の実現度 | × | ◯ | ◎ |
| 上司指示への適合度 | △ | ◎ | △ |

### 3.2 各案のページ別イメージ

#### 案 A: テンプレ型

**全事業のページが同じレイアウト**。違うのはメインカラー1色だけ。

```
[トップ]      [コールセンター]   [AI OPS]      [財務]
┌────────┐   ┌────────┐        ┌────────┐    ┌────────┐
│ ナビ   │   │ ナビ   │        │ ナビ    │    │ ナビ   │
│        │   │        │        │         │    │        │
│ Hero   │   │ Hero   │        │ Hero    │    │ Hero   │
│ (緑)   │   │ (緑)   │        │ (青)    │    │ (灰)   │
│        │   │        │        │         │    │        │
│ 同レイ │   │ 同レイ │        │ 同レイ  │    │ 同レイ │
│ アウト │   │ アウト │        │ アウト  │    │ アウト │
└────────┘   └────────┘        └────────┘    └────────┘
```

- **長所**: 実装最速、運用最楽、ブランド統一感最強
- **短所**: 凡庸。**「数百万かけた感じ」は絶対に出ない**。SaaS テンプレに見える
- **上司指示適合**: 「尖り」と「事業別トーン」が満たせない

#### 案 B: 中庸型（推奨）

**ナビ・フッター・タイポ・グリッドは共通だが、事業ページは大きく違う表情**。

```
[トップ]          [コールセンター]      [AI OPS]            [財務]
┌────────┐       ┌────────────┐        ┌────────────┐      ┌────────────┐
│ ナビ   │       │ ナビ        │        │ ナビ         │     │ ナビ        │
│        │       │             │        │              │     │             │
│ 全事業 │       │ 現場写真    │        │ データ可視化 │     │ 静謐な     │
│ 紹介   │       │ 大胆        │        │ 動画         │     │ 文字組      │
│ 章立て │       │ 暖色        │        │ ダーク + 青  │     │ ダーク      │
│        │       │             │        │              │     │ グリーン    │
│ ストー │       │ HISTORY     │        │ HISTORY      │     │ HISTORY    │
│ リー   │       │ SOLUTION    │        │ SOLUTION     │     │ SOLUTION    │
│ テラー │       │ CASE        │        │ CASE         │     │ CASE       │
│ 構造   │       │             │        │              │     │             │
│        │       │ 採用 CTA    │        │ 法人 CTA     │     │ 提携 CTA    │
│        │       │ 強い        │        │              │     │             │
└────────┘       └────────────┘        └────────────┘      └────────────┘

  ↓ 共通          ↓ 共通                ↓ 共通                ↓ 共通
   フッター        フッター              フッター              フッター
```

- **長所**: 上司の「尖り」と「事業別トーン」を両立。Apple 型の安定設計
- **短所**: 設計時に「メタ層 / 事業層の境界」を明確化する必要あり
- **上司指示適合**: ◎

#### 案 C: 分断型

**事業ごとに完全に別世界観**。

```
[トップ]          [コールセンター]      [AI OPS]            [財務]
┌────────┐       ┌─────────────┐       ┌─────────────┐    ┌─────────────┐
│ 独自   │       │ 独自ナビ    │       │ 独自ナビ    │    │ 独自ナビ    │
│ ナビ   │       │             │       │              │    │             │
│        │       │ 独自        │       │ 独自         │    │ 独自         │
│ 動画   │       │ 全画面      │       │ 黒背景       │    │ 細密な      │
│ 主役   │       │ 動画        │       │ 3D          │    │ 文字組      │
│        │       │             │       │              │    │              │
│ ロゴも │       │ ロゴ拡大    │       │ ロゴ縮小     │    │ ロゴ別配色  │
│ 違う   │       │             │       │              │    │              │
└────────┘       └─────────────┘       └─────────────┘    └─────────────┘

   ↓共通フッター   ↓共通フッター         ↓共通フッター      ↓共通フッター
```

- **長所**: 「尖り」最大化、各事業を完全に演出できる
- **短所**:
  - **同じ会社のサイトに見えない** → ブランド資産が分散
  - SEO: 内部リンク構造が崩れ、Google からの評価が分散
  - 採用: 「GIFT」というブランドの認知統合に失敗
  - 開発: 事業ページごとに別プロジェクトのような複雑度
  - 更新: 共通要素の変更が困難
- **上司指示適合**: 「尖り」は満たすが、「ブランディング」「採用」と衝突

## 4. 推奨案: 案 B（中庸型）— 詳細設計

### 4.1 なぜ案 B が最適か

1. **上司の「尖り」要求は、メタ層を共通化したまま事業層で実現可能**
   - メインカラー / 写真トーン / モーションを事業層で大胆に変えれば、訪問者にとっては「全然違う表情のページ」に映る
   - メタ層（ナビ / フッター / タイポ / グリッド）は無意識にしか認識されないので、共通でも「尖り」は損なわれない
2. **「数百万かけた感じ」は構造ではなく素材と細部で出る**
   - 案 A のレベルでも、写真と動画と細部演出が高品質なら高単価サイトに見える
   - 案 C のように構造まで分断する必要はない
3. **運用とブランド資産の保護**
   - 案 C はメンバー入れ替え・新事業追加・キャンペーンなど **将来変更時の負荷** が爆発する
   - 案 B なら新事業を追加する時、メタ層に乗せるだけでサイト全体に統合できる
4. **Apple モデル**
   - 大手の高品質コーポレートサイトは、ほぼすべてこのモデル
   - rebita 20th も、よく見ると章ごとにトーンを変えながら共通グリッドで支えている

### 4.2 メタ層の SSOT（Source of Truth）案

実装時の SSOT（拘束力のあるデザインルール）を以下の構成で定める想定。**実装は別担当だが、リサーチ側で骨子を提案する**:

```
docs/design-system/
├─ 01_meta_layer.md       # 全事業共通ルール（拘束）
├─ 02_business_layer.md   # 事業ごとの可変範囲（自由）
├─ 03_typography.md       # フォント階層・サイズ・行間
├─ 04_grid.md             # グリッド・スペーシング
├─ 05_motion.md           # モーション基底ルール
└─ 06_copy_voice.md       # コピー様式（対比の1行ルール等）
```

> ※ これらは Phase D（素材発注前）に作成する想定。本フェーズではあくまで骨子提案。

### 4.3 事業ページのトーン仮置き（叩き台）

| 事業 | メインカラー | アクセント | 写真トーン | モーション強度 | 顔出しなし様式 | 章立てパターン |
| --- | --- | --- | --- | --- | --- | --- |
| トップ | コーポレート緑（既存）+ ダークグレー | 白 | 環境・抽象画像 + 数値タイポ | 中（ストーリーテラー演出） | 集合・数値型 | 3章（コール / AI / 財務） |
| コールセンター | 暖色（オレンジ寄り or 既存緑の暖トーン） | アイボリー | **現場・オフィス・電話越しの空間** | 控えめ | **環境ショット型**（桐山組型） | 採用主目的の章立て |
| AI OPS | **テック青（指示通り）** + ブラック | 蛍光ライム or 白 | データ可視化 / 抽象アニメ / 細密グラフィック | 高（テック感を出す） | データインフォグラフィック型 | HISTORY: AI 業界 / SOLUTION: GIFT の AI / CASE: 導入実績 |
| 財務コンサル | ダークグリーン or チャコール | 金 or アイボリー | 静謐・編集的・抽象 | 控えめ（重厚） | 第三者推薦型 + シルエット | HISTORY: 中小企業財務課題 / SOLUTION: 伴走 / CASE: 実行額 |
| メンバー一覧 | コーポレート緑 | 黒 | **イラスト**（線画 or 似顔絵） | 中 | **イラスト型** | 個別ページへ |
| 採用（コールセンター以外） | コーポレート緑 | 暖色 | 環境ショット中心 | 中 | 環境型 | 募集ポジション+価値観 |

### 4.4 ストーリーテラー演出の骨子（トップページ）

rebita 学びを最小実装にした構成案:

```
セクション 1: ヒーロー
  └─ 「対比の1行」タグライン + 動く背景（数秒のループ動画 or 抽象アニメ）
セクション 2: 数値で語る GIFT（顔出しなし様式）
  └─ コールセンター300名 / AI 導入企業数 / 累計実行額 等
セクション 3: 章 1 — コールセンター
  ├─ HISTORY: 通信業界の変化
  ├─ SOLUTION: GIFT の自社運営×教育主導
  └─ CASE: 数値 + 取引先カテゴリ → 専用ページへ
セクション 4: 視覚呼吸（intermission）
  └─ 大きな数値タイポ or 環境写真
セクション 5: 章 2 — AI OPS
  ├─ HISTORY / SOLUTION / CASE
  └─ → 専用ページへ
セクション 6: 視覚呼吸
セクション 7: 章 3 — 財務
  ├─ HISTORY / SOLUTION / CASE
  └─ → 専用ページへ
セクション 8: メッセージ（多声性）
  └─ 取引先・社員・応募者等の声
セクション 9: クロージング + Contact CTA
```

## 5. 役員レビュー時のチェックポイント

役員に確認してもらうべき論点（順番が重要）:

### Step 1 — メタ層と事業層の概念合意
- 「事業ごとに表情を変えていい範囲」と「変えてはいけない範囲」をこの構造で進めることを合意

### Step 2 — 案 B 採用合意
- 案 A / B / C の比較を見て、案 B でいくことに合意

### Step 3 — 各事業のトーン仮置き合意（4.3 表）
- 「AI = テック青」は確定として、コールセンター / 財務のトーンを役員間で決める
- 特に **コールセンターを暖色にするか、既存の緑をそのまま使うか** は意見が分かれやすいので議論枠を取る

### Step 4 — トップのストーリーテラー演出合意（4.4）
- 章数（3章 = 事業数）でいくか、追加章（沿革 or 採用）を入れるか
- 視覚呼吸（intermission）を入れるか

### Step 5 — 案 B での「尖り」許容ライン
- AI OPS ページで「黒背景 + 派手モーション」までやって OK か
- 財務ページで「動きほぼゼロの誌面型」まで振って OK か
- 役員から「ここは丸めて」が出る前提で、**先に振り切った提案を持ち込む**

## 6. 採用しなかった案へのフォロー

### 6.1 案 A を採用しなかった理由
- 上司発言「役員から丸めて欲しいって言われるぐらい尖り切る」に矛盾
- 「数百万かけた感じ」は素材だけで出せるが、案 A だと **テンプレ感が抜けない**
- ただし **MVP として案 A → 段階的に B に育てる** という選択肢はあり（予算・時間制約が厳しい場合）

### 6.2 案 C を採用しなかった理由
- ブランド一貫性が崩壊し、**「数百万かけた感じ」と「バラバラなサイト感」は紙一重**
- 運用負荷が爆発し、メンバー追加・新事業追加で都度デザインし直しが必要
- SEO の内部リンク構造が壊れる
- ただし **AI OPS ページだけ案 C 寄りに振り切る** という変則も可能。ここは Phase C で議論

## 7. リスクと対策

| リスク | 対策 |
| --- | --- |

| コールセンター採用ページで「顔出しなし」が応募率下げる | Phase C で例外設計（採用ページのみ顔出し OK 等）を決める |

## 8. Phase C への持ち込み素材

Phase B で確定した（案 B 採用 + 4.3 のトーン仮置き）を前提に、**Phase C で詰めること**:

1. **「顔出しなし」様式の最終選定**
   - メンバーページのイラスト発注先候補と参考タッチ
   - コールセンター採用ページの環境ショット撮影プラン
   - AI OPS ページのデータ可視化ビジュアル候補
   - 財務ページの第三者推薦コメント収集計画
2. **コールセンター採用ページの例外設計**
   - 完全顔出しなしを貫くか、応募率を取って顔出し OK にするか
3. **イラストの様式絞り込み**
   - 似顔絵（Ra-tel 型）/ フラットイラスト（講談社型）/ 動物キャラクター（GEAR8 型）/ 線画（バケモノ型）から 1 つ

## 9. 開発担当への引き継ぎ事項（暫定メモ）

> 本プロジェクトは「コードを変更しない」ため、ここは将来の開発担当者への申し送りメモ。実装着手はリサーチ完了後。

- **Tailwind の設計思想**: `tailwind.config.ts` を **メタ層（共通）** と **事業層トークン（事業ごと）** に分離
  - 例: `gift.green` 系はメタ層、`callcenter.warm`, `aiops.tech-blue`, `finance.charcoal` 等を事業層トークンとして追加
- **App Router の構造**: `/services/[業種]` で事業ページを分け、各ディレクトリ配下に **そのページ専用の CSS 変数オーバーライド** を入れる
- **コンポーネント共通化**: 章立て構造（HISTORY / SOLUTION / CASE）は共通コンポーネント化し、内部のトーンだけ事業層で変える
- **動画の出し方**: AI OPS の Hero 動画はサイレント・自動再生・loop。LCP のため `poster` で初期画像を見せる
- **アクセシビリティ**: 動画には `prefers-reduced-motion` 対応を必須化
