## ご質問1 — メインドメインをVercelへ切り替えると `new.gift-inc.org` はどうなるか

結論から申し上げますと、**`new.gift-inc.org` には何も起こりません。これまで通り稼働し続けます。**

理由は、DNSレコードが名前ごとに独立しているためです。今回の切替で変更するのは **apex と www のレコードのみ**で、その他のサブドメインはそれぞれ別レコードのため影響を受けません。

| 名前 | 向き先 | 今回の切替で変更されるか |
|---|---|---|
| `gift-inc.org`（apex） | さくら → **Vercel** | ✅ はい（これが今回の変更） |
| `www.gift-inc.org` | さくら → **Vercel** | ✅ はい（これが今回の変更） |
| `new.gift-inc.org` | **Google Cloud** | ❌ いいえ（別レコード・変更なし） |
| `aiops.gift-inc.org` | Vercel（既に稼働中） | ❌ いいえ（変更なし） |
| `dashboard.gift-inc.org`（予定） | さくら | ❌ いいえ（別レコード） |

`new.gift-inc.org` は Google Cloud を指す独立したレコードで、さくらやメインドメインに一切依存していないため、切替後も**そのまま稼働し続けます**。（念のため：`new.gift-inc.org` は弊社のVercelサイトとは別の、Google Cloud上の別サイトです。弊社サイトが透けて見えているわけではありません。）

**1点だけご認識いただきたい点（問題ではなく、ご判断事項です）：** 新メインサイトがVercelで公開されると、**「GIFT inc.」の公開サイトが同時に2つ**存在することになります ― 新しいメインサイト（`gift-inc.org`／Vercel）と `new.gift-inc.org`（Google Cloud）です。技術的には問題なく、安全です。ご確認いただきたいのは、**新メインサイトと並行して `new.gift-inc.org` を公開したままにしてよいか**、それともどこかの時点で停止・転送するか、という点だけです。いずれにせよ**メインドメインの切替を妨げるものではなく**、別途いつでも対応可能です。

## ご質問2 — 正規URLは apex か www か／リダイレクト方針

- **推奨：正規URLを apex（`gift-inc.org`）とし、`www` → apex へ 308 リダイレクト。**
- **7/8障害の証明書問題は、Vercel移行で自動的に解消します。** Vercelは apex と www の**両方に有効な証明書を自動発行**するため、現在の「www側の証明書不一致（`*.sakura.ne.jp` がwwwを含まない）」は起きなくなります。
- **本日の実測（参考）：** `www.gift-inc.org` は現在も証明書不一致のままで、HTTPSアクセスは証明書エラー＋403を返します。これはさくら側の状態で、wwwがVercelに載れば解消します。
- **Vercel設定：** apex を Vercel へ向け、www も Vercel に登録した上で www→apex のリダイレクトを設定します。apex を正規とする理由は、ブランドURL・既存の被リンク・印刷物等がすべて apex を使っているためです。

## ご質問3 — 旧WordPressで残すURL一覧

旧サイトの `wp-sitemap.xml` から全URLを取得しました。**旧サイトは5ページ構成**（ブログ記事なし）＋フィード＋ダッシュボードです。以下がリダイレクト対応の全対象です。

| 旧URL | 内容 | → 新URL | 備考 |
|---|---|---|---|
| `/` | トップページ（株式会社GIFT） | `/` | 同一パス・新コンテンツ。リダイレクト不要 |
| `/about/` | 会社概要 | `/company` | 301（対応済みマッピング） |
| `/privacypolicy/` | プライバシーポリシー | `/privacy` | 301（対応済みマッピング） |
| `/lstep/` | Lステップ | **要ご判断** | 下記参照 |
| `/lsteprpa/` | RPAでLステップ更新を自動化 | **要ご判断** | 下記参照 |
| `/feed/` | WordPress RSSフィード | `/`（または404のまま） | 新サイトにフィードなし。重要度低 |
| `/DashBoard/` | ダッシュボード | `dashboard.gift-inc.org` | ご質問5参照（rewriteは作りません） |

**ご判断をお願いしたい点：** `/lstep/` と `/lsteprpa/` は旧サイトの**主力事業ページ**であり、被リンクが最も付いている可能性が高いページです。新サイトはAIOps軸へ再編しており、対応する専用ページがありません。転送先について以下からご指定ください。

- **→ `/services/aiops`**（推奨・LステップをAIOpsに統合する場合。内容的に最も近い＝自動化）
- **→ `/`**（Lステップを終了する場合の無難な既定）
- **専用のLステップページを新設**（Lステップが現在も提供中の事業である場合のみ）

**一覧の網羅性について（弊社側で対応済み・そちらでの作業は不要です）：** 上記の一覧は、旧サイトの `wp-sitemap.xml` に加え、旧サイト内の**全内部リンクを独自に巡回**して作成しており、両者が一致しています。したがって、これが現在有効な旧URLの**完全な一覧**です。（外部サイトからの被リンク一覧は Google Search Console から取得できますが、これはSEO上の話であり、リダイレクトには不要です。必要になった場合も**開発側で直接確認**しますので、マネージャー側でのご対応は不要です。）

## ⚠️ 追加で判明した重要事項 ― もう1つのWordPressサイト「SUPPORT 997」

旧ドメインを入念に調査（サイトマップ＋過去アーカイブの全巡回＋Googleインデックス確認）した結果、移行計画で把握できていなかった**別の独立したWordPressサイト**が見つかりました。

- **URL：** `https://gift-inc.org/support997/`
- **内容：** オウンドメディア「**SUPPORT 997｜中小企業のためのお役立ちメディア**」。RPA・Excel・Googleドライブ・PowerPoint・OCR・DX・補助金/働き方などの**ハウツー記事48本（URL計49件）**。現在も**稼働中かつ更新中**です（サイトマップは2026年7月9日に再生成されています）。
- **なぜ重要か：** これはダッシュボードと同様に、**apex配下（さくら）に存在します。** apexをVercelへ切り替えると、**49件すべての `/support997/*` URLが404になります。** ハウツー記事は検索流入や被リンクが最も付きやすく、ドメインの中で**SEO価値が最も高いコンテンツ**の可能性が高いため、気づかず失うと打撃になります。

**切替前にSUPPORT 997について以下のご判断が必要です：**

1. **今後も継続する**メディアでしょうか？それとも縮小・終了予定でしょうか？
2. **継続する場合の保全方法** ― 推奨は、ダッシュボードと同じく**専用サブドメイン**（例：`media.gift-inc.org`）をさくら側に用意し、旧 `/support997/*` を301リダイレクトする方法です。（WordPressのため、さくら側でサイトURLを一度移行する作業が必要です。）
   - *労力の小さい代替案*（ただしapexとさくらが再結合）：Vercelのプロキシで現行URLのまま維持。
   - *コンテンツを残さない場合*：全URLを新サイトへ301。
3. **Google Analytics** をお持ちであれば、アクセス数からSEO価値の大きさが判断できます。

この点が決まるまで、`/support997/` は**apex切替のブロッカー**（ダッシュボードと同種の課題）となります。

## ご質問4 — 切替の実施希望日と立ち会い時間帯

切替日は逆算で決まります ― **切替日 ＝ フェーズ1（`dashboard.gift-inc.org` 設定）完了 ＋ テスト約3日 ＋ TTL変更（前日）**。フェーズ1が完了すれば、切替日は自動的に確定します。以下、**各前提が整った場合の提案スケジュール**です。

| 日程 | 内容 |
|---|---|
| **7/13（月）** | フェーズ1：さくら側で `dashboard.gift-inc.org` を設定（vhost＋SSL）。※SUPPORT 997を残す場合は、そのサブドメインも並行して用意。 |
| **7/14（火）〜7/16（木）** | フェーズ2：新サブドメインで実業務テスト（約3日）。ログイン・全ページ表示・DB読み書き等を確認。 |
| **7/17（金）** | apexのDNS TTLを300秒へ低下（早めに下げても支障なし。切戻しを数分で済ませるため）。 |
| **7/20（月）午前** | **メインドメイン切替（apex＋www → Vercel）。** 予備日：7/21（火）。 |

※ 7/20（月）は海の日（祝日）ですが、貴社は当日も稼働とのことですので、この日に実施します。当日は切替後 **1〜2時間**、双方で動作確認・即時切戻しのため待機します。

**この日程が成立する前提：**
1. ご判断事項（apex方針・`/lstep` 転送先・**SUPPORT 997の扱い**）を **7/13（月）まで**に確定。
2. さくら管理者が **7/13（月）にフェーズ1へ着手**可能。
3. SUPPORT 997を残す場合、その保全（サブドメイン移行）もフェーズ1〜2に含めて完了。
4. **各担当者が、自身の外部API・外部連携・外部リンクがメインドメイン（`gift-inc.org`）に依存していないことを確認・報告済み。** メインドメインを参照している連携が1つでも残っている場合、切替後に動作しなくなる可能性があるため、**全員の確認が取れるまで切替は実施しません。**

**納期について正直に申し上げます：** **7/20（月）はあくまで目標であり、上記4点（特に各担当者の外部連携の確認）が揃って初めて確定します。** 上記いずれかが遅れれば、切替日も同じだけ後ろ倒しになります。「今週中」「明日」の切替は、テスト未実施のまま行うことになり **7/8障害の再発リスクが高いため、推奨いたしません。** 目標公開日が決まっている場合はお知らせください。上記クリティカルパスに収まるか即座に判定してお返しします。

## ご質問5 — `gift-inc.org/DashBoard/` に rewrite 等を作らない件

**承知しました。**Vercel側で `gift-inc.org/DashBoard/` をさくらへ転送する rewrite（プロキシ）は**作成しません。** これは7/8障害の原因（ダッシュボードとメインドメインの再結合）そのものであり、ご指示に完全に同意します。

**1点、認識合わせをお願いします：** メインドメインをVercelへ向けた後、さくらは apex 宛の通信を受けなくなるため、**旧パス `gift-inc.org/DashBoard/` は404になります。** よって、**フェーズ2のテスト期間中に、ダッシュボードの利用者・ブックマークをすべて `dashboard.gift-inc.org` へ移行**しておく必要があります。

- **任意のご提案：** 旧ブックマーク救済のため、`gift-inc.org/DashBoard/` → `dashboard.gift-inc.org` への**301リダイレクト**を設定することも可能です。これは**「リダイレクト」であって「rewrite（プロキシ）」ではなく**、さくらには一切触れず・再結合も起こしません。不要であれば何も置かず404のままとします。**ご希望をお聞かせください。**
